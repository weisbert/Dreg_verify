## 2. 「零遗漏」怎么保证（五道锁 + 三条硬护栏）

- **L1 契约表 = 单一真相。** `docs/GUI_v2_能力契约.md`（+ 同名 csv），每条能力一个 ID（`C-001`…）。来源七处，缺一处就有漏：① 推进方案 §4.1–4.4 ② Design prompt §10 ③ `审计_真值表能力对照` 表 A/B/C ④ `GUI现状清单` §1 控件树 / §3 对话框 / §5 工作流 / §7 违反项 ⑤ 6 月 `通用功能丢失审计` 12 项 ⑥ **gui.py 代码普查**（每个 handler、每个 QDialog/QMessageBox 流程、settings 键全集、`~/.dreg_verify_edits.json` schema、6 个快捷键、9 种单元格颜色态、STATUS_HELP 8 档、FOUND_IN_LABEL）⑦ backlog TASK-007 / TASK-015。每行：ID | 能力 | 旧入口（方法名） | 后端 API | 类别（保留/合并/降级/删除/新增） | v2 落点（Design 映射表填） | 测试 ID | 状态。
- **L2 Design 映射表 ⟂ 契约。** 每个非「删除」ID 必须有 v2 落点。Design 没给的，主控按合理默认补位，单列「补位项」给用户过目——**不停工等**。
- **L3 测试按 ID 命名。** v2 每条 GUI 测试名含契约 ID（`test_c042_…`）；`tools/contract_check.py` 读契约表，任一非删除 ID 没有 ≥1 条通过的测试 → 红。
- **L4 旧测试退役规则。** 删一条『排查(旧)』测试前，契约表里必须登记它对应的 v2 测试 ID；只准对齐、不准弱化断言。
- **L5 parity 对抗 review。** 上线前 review 加一个维度：agent 拿契约表逐条在 offscreen v2 上实操验证，不看代码看行为。
- 硬护栏：**byte-gate 6 sha 每步必跑**；generator.build/report、旧 CLI 默认、fortest_writer 逐字节不变；**用户机上的持久化文件**（`~/.dreg_verify_gui.json`、`~/.dreg_verify_edits.json`）旧格式必须仍可载入（同事的手填期望不能因升级丢）。**写 edits 文件按路径桶合并、不整桶重建**（A3 审计坑④）；『缺前缀是否强制生成』做成开关后默认仍 True（A3 实测改 False 改 .sv 字节）。

- **多机并行**：每次 push 前看 `git log origin/main`；worktree 分支只由主控合。
- **Design 与契约冲突**：契约优先，冲突单列给用户；Design 的视觉/布局照单全收。
- **公开仓**：docs 只用 mirror 名；截图与原型留 `refactor_notes/`（ignored）。

## 7. 架构步输入：分析结果 `an` 的缺口（A4c 等价性对照实测，B3 必读）

`inputs_table.input_rows(an)` 已能在 mirror 上逐格复刻旧门面的输入信号表（18 信号零差异），但下面 6 处是 an 本身没带、v2 想做到契约就必须补的（都是 additive 加字段，不动 .sv 路径）：
