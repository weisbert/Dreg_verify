# Topout 默认门面通用功能丢失审计报告

**总览：** 经对抗验证，确认新 Topout/SignalView 默认门面相比旧门面，丢失了 **13 类去重后的通用功能**（与视图无关、对 Topout 同样有意义、designer 日常要用），其中 **3 类高危**(持久化相关)。另有一批被误报/或属 by-design 只放排查旧分页，已澄清排除。所有结论均以 HEAD 代码 file:line 为据。

> 注：原始结论里大量条目语义重复（导出 .sv 选项对话框 / scope / comments / sv_summary / owner_in_msg 被拆成 10+ 条），下面已按"一个功能一条"合并。

---

## 一、用户已点名的 3 条

### #1 保存/恢复/切换配置 —— 真丢了一半，另一半是从未有过的新需求

这条用户的诉求拆成两件事，结论不同：

**(a) 完整配置导出/导入(.json)在 Topout 默认门面够不着 —— 真丢了。** severity: high
- 旧有：`导出配置…`/`导入配置…` 按钮在 `gui.py:1796-1820`，挂在 legacy「排查(旧)」分页；序列化器 `_collect_config`(gui.py:4466-4500) 收全套(signals_checked + 覆盖度/max_tests/级联/尾缀/include_risky + probe_prefixes + force + suffix_override + logic_overrides + edits含手填期望 + neg_only + mux_*)；`on_export_edits`(4559)/`on_import_edits`(4592)。
- 新缺：SignalView 工具条只有 5 个按钮(`设置探针前缀…/预览选中.sv/导出.sv…/导出报告/回填for_test`，gui.py:835-845)，无导出/导入配置；类体内 grep `on_export_edits|on_import_edits|_collect_config` = 0；全文件无 menuBar 兜底。**更关键**：`_collect_config` 只读 MainWindow legacy 状态(self._edited/self.coverage)，**完全不触碰 `topout_view.edits`**，所以即便切到旧分页导入配置也不会反映进 Topout，反过来 Topout 手填的期望也无法导出。
- 恢复要点：① 加全局菜单栏「文件→导出/导入配置…」(对所有视图通用，最省事)或在 SignalView 工具条加两按钮委托回 `main.on_export_edits/on_import_edits`；② 扩展 `_collect_config` 把各 SignalView.edits 一并序列化(新键 `view_edits`)；③ 导入时反序列化回 `topout_view.edits` 并 `refresh()`，覆盖度需同步设到 `SignalView.cov`(独立 combo)。
- **判定：真丢了**（入口 + 数据通道双缺）。

**(b) 在多份命名配置之间切换 —— 误判，从未存在。**
- HEAD 与旧版均无命名配置/配置列表概念：grep `config_list|profiles|命名配置|配置列表` = 0 命中。重构未删除任何此类能力，它是从未有过的新需求，不属"重构丢失"。

### #2 designer 手填期望(没填才 auto_out)且期望值可复用保存 —— 真丢了

severity: high（这是 3 条里最致命的一条，实际牵涉两个持久化层）

- 旧有：旧门面手填期望走 `self._edited`，全程持久化——`_persist_edits`(gui.py:4309-4344) 即时序列化(含 `designer_expected`，见 `_ROW_PERSIST_KEYS` gui.py:50)按 Excel 路径写 `EDITS_PATH`；载表时 `_restore_edits`(4346)恢复并提示「已恢复 N 个信号的测试项编辑(含手填期望)」(gui.py:2727-2729)。
- 新缺：Topout 手填期望落在 SignalView 自带的**纯内存** `self.edits`(gui.py:672)，写入点 `_commit`(1224)/负向(1407)，导出时由 `_compute_edited`(1440) 现算供 `render_sv`(1550) —— **会话内功能完整**，但：
  - **`_persist_edits` 从不序列化 `topout_view.edits`**(4324-4341 只看 self._edited/self._mux_*)；
  - **每次载表无条件 `self.topout_view.edits.clear()` + 各子视图 `v.edits.clear()`**(gui.py:2733-2735)，且**无任何对应的 SignalView 恢复路径**。
  - 结论：designer 默认进 Topout 手填的期望，**关 GUI 或换表即丢，下次打开是白纸**，"期望值可复用保存"在默认门面完全不成立。
- 恢复要点：在 `EDITS_PATH` 桶里按 `view_id` 增子键 `sv_edits`；SignalView 加 `_serialize_edits`/`_apply_edits_bucket`(复用现成 `_serialize_rows`@87/`_serialize_mux_vecs`@118，只存可重算字段、load 后经 `_recompute_col` 重算 auto 以免改表后陈旧假绿)；把 2733-2735 的无条件 clear 改为 clear 后调 restore(在 refresh 重建 models 之后)；每个编辑写入点回调 `main._persist_edits`(复用 `_persist_suspended` 批量挂起)。
- **判定：真丢了**（auto_out 兜底逻辑本身在 Topout 是好的，丢的是"手填期望的持久化/换表恢复/可复用"）。

### #3 导出 .sv 的注释/计数开关 + 导出时提示用例数/反向数 —— 大部分真丢，"用例数"那半在

severity: medium

**真丢的部分：**
- 旧门面有完整导出选项对话框 `_ask_export_options`(gui.py:6311-6362)：scope(全部/仅正向/仅负向) + comments(加注释，默认关) + owner_in_msg(默认开) + sv_summary(末尾测试汇总，默认开)，全部记忆到 settings。
- 新缺：`SignalView.on_export_sv`(gui.py:1541-1561) 直接弹文件框→`provider.render_sv(only, mode, maxt, exh, edited)`，**无任何选项对话框**；`_TopoutProvider.render_sv`(gui.py:513) 签名 `comments=True` 写死、且不传 sv_summary/owner_in_msg → 后端落 False(topout.py:833)。即 **comments 恒 True(还与旧默认 False 相反)、sv_summary 恒不带计数器块、owner 恒不带、scope 完全没有**。底层 `render_topout_sv`(topout.py:832-840) 其实已接受 comments/sv_summary/owner_in_msg，纯是 GUI provider 包装层写死丢了；CLI `--topout` 已正确接线(cli.py:294-296)，证明仅 GUI 漏接。
- **scope(仅正向/仅负向)是结构性缺失**：topout.py / pageviews.py grep `positive_only|negative_only` = 0 命中，后端连过滤参数都没有(旧门面靠 `_vector_overrides` gui.py:6122-6160 实现)。Topout 本身支持加/删负向，却无法只导正向(给仿真)或只导负向(做验证自检)。

**导出弹窗的"用例数"那半 —— 在(非丢失)：**
- `on_export_sv` 弹窗(gui.py:1557-1561) 已显示 `信号/断言块/向量/记账` 四项，其中"向量数 n_vectors"就是用例数，负向已并入总数。
- **但"反向数"细分丢了**：弹窗不取 `s.get("n_negative")`(数据其实已在 summary 里，topout.py:827)，也无 designer 手填/auto_out 兜底拆分(更底层原因：topout summary 根本没聚合 `n_designer`，topout.py:826-828 只有 n_vectors/n_negative)。

- 恢复要点：① 给两个 provider 的 `render_sv` 加 `comments/sv_summary/owner_in_msg/scope` 形参透传(后端已就绪，零成本)；② 在 `on_export_sv` FileDialog 后复用/抽出 `_ask_export_options`(共享 export_comments/export_sv_summary/export_owner_in_msg 记忆键)，默认 comments 改回 False；③ scope 需在 `build_for_topout`/`render_topout_sv` 补 positive_only/negative_only(复用旧 `_vector_overrides` 语义，按 `vec.is_negative` 过滤)；④ topout summary 补 `n_designer`(per-block 已有 sv_writer.py:293，求和即可)，弹窗补 negative/designer 拆分提示。
- **判定：注释/计数开关 + 反向数提示 + scope = 真丢；用例数提示 = 已在。**

## 二、新发现的其它通用功能丢失

## 四、建议恢复优先级

1. **手填期望持久化/换表恢复(#2)** — high，致命：默认门面手填即丢，"期望可复用"完全不成立，且 2733-2735 的无条件 clear 是 silent data loss。
2. **完整配置导入/导出 + Topout edits 入桶(#1a)** — high：与 #2 同一持久化框架，"配置即交付物"跨机迁移入口，建议与 #2 一并做。
3. **信号勾选持久化(N1)** — medium：同框架顺手补。
4. **导出 .sv 选项对话框(#3：comments/sv_summary/owner_in_msg)** — medium，后端已就绪纯接线，零成本。
5. **scope 仅正向/仅负向(#3)** — medium，需后端补 positive_only/negative_only 过滤(复用旧 `_vector_overrides` 语义)。
6. **_confirm_dup_labels 透传(N9)** — medium：防静默导出非法 SV，topout 丢弃了已算好的 dup_labels。
7. **report/fortest 的 only 过滤(N6)** — medium：`.sv` 已有 only，对称补即可。
8. **RTL 补充逻辑 logic_overrides 接 Topout(N4)** — medium：后端需新增形参穿透。
9. **单点覆盖度 sig_cov(N3) + mux_data 手填(N8) + 导出 nets.txt(N5)** — medium：各自独立小改。
10. **覆盖度下拉持久化(N2) + 单信号 CSV 导出(N7) + 报告/回填完成提示计数** — low：体验优化。

所有恢复点的底层引擎(render_topout_sv 的 comments/sv_summary/owner_in_msg、build_for_topout 的 only、generator 的 sig_cov/logic_overrides/mux_data/dup_labels)大多已存在，主要是 **SignalView/provider 包装层未接线**；唯 scope(positive_only/negative_only) 与 topout summary 的 n_designer/dup_labels 聚合需在 topout.py 补少量后端。
