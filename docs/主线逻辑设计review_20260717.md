## 执行摘要

1. **用户的直觉是对的：3bde25d 修的只是"桥接支"的串门；同一机制在"直接命中/_ls 命中"的扇出支上原样存在**——带门 dft 行的 G 列去向是 to_crg 还是 to_ls，工具产出完全相同（E2 实验坐实），因为 **dft 页 G 列（去向 suffix）全仓库无任何读取点**，而它正是消歧"哪支过门"的第一手信息。
2. 门判定的三条判据（B 列=门、E 形态白名单、`_to_dft` 后缀=门前网）**全部是未经 SE 确认的反向工程**，且每条都被实验打穿：E="A?0:B"（门写在 A 列）→ read_dft 把功能输入当门、改名边把输出解析成**门寄存器的透传**，status=ok（E1）；`B[0]?0:A`/`(B)?0:A`/`B?1:A` 等拼法**静默漏门**（E7）；dft 同名两行 → `wb.dft` last-wins 与改名边取舍互相污染、另一行静默不验（E3），与 R35 regmap first-wins+告警的教训**不一致**。
3. 撞名解析层没有任何冲突告警：build_index 候选撞车静默选行序在前者（E5）、直接命中静默压掉 dft 改名边（E6）、Topout 页同名行产出重复 assert id 且 dup_labels 不报（E9）。
4. 门策略如今**散在 6 处**（resolve_root 3 处 + analyze_signal 2 处 + _result_gate_info 1 处），3bde25d 是第三次往里加分支——当前各处一致（详查过），但"改一处忘五处"结构性成立。
5. 治本仍是 R41 的结论：**scan_rtl 真 nets 当裁判至今一行都没消费**（`rtl_nets`/`known_missing` 生成侧 0 引用；cf4cc88 只做了导出侧）。新主线的 claims 通道（R42）已把探针/force 网聚齐，**插桩成本比 R41 时更低**——最小可行版见 D 节。
6. 便宜且高杠杆的三件事：read_dft loud 化（含 `?` 不匹配即记账 + 同名重复告警 + 校验 E 条件字母对应 B 列）；消费 dft G 列做门归属交叉核对（Excel 侧就能堵 E2）；门判定收口成单函数。

## A · "猜"的决策点清单

### A1 🔴 out_base 兜底门（直接命中/_ls 命中支）——3bde25d 未覆盖的另一半

【实验 E2】`topout.py:428-429`（logic）/ `513-514`（mux）：非桥接根一律按源 `out_base` 查 `wb.dft` 兜底套门。

- **猜什么**：同名带门 dft 行的门"就是"本支路径上的门（一名一观测）。
- **触雷条件**：logic 源扇出，**带门支去 to_crg/其它、Topout 验的是 _ls 支或直连顶层支**（en_cnt 的镜像拓扑）。E2 实测：G=to_crg 与 G=to_ls 两种真值下 `iddq_evidence` 完全相同 `(True, True, 1)`。
- **后果**：假 iddq 输入行 + 假 DFT 拍（拍 force iddq=1 断言 0，真端口不过门 → sim 假红；输入集与 for_test 失配）。若负向/期望值巧合还可能假绿。
- **护栏**：无。`dft_bridged` 只保护桥接支；dft 行 G 列去向从未被读。
- **建议**：`read_logiclike_page` 给 dft 行补读 G 列 → 兜底套门前交叉核对"带门行去向"与"本支去向"（_ls 命中 ⇔ G∈{to_ls,ls}；直连顶层 ⇔ G 空/top）；不一致 → 不套门 + 块顶 ⚠"门归属存疑"。

### A2 🔴 read_dft 盲信"B 列=门"，E 列正则不校验条件字母

【实验 E1】`excel_model.py:960-973`：E 只要长得像 `X?0:Y` 就认门，门原文无条件取物理 B 列——E 里的字母 A/B/C 本是列引用，工具却从不对应。

- **触雷条件**：设计师把门写在 A 列、功能写在 B 列（E="A?0:B"，语义完全合法）。
- **后果（E1 实测）**：`read_dft` 记 gate_base=功能网 src_sm；`_dft_rename_edges` 反向把门 my_gate 当唯一功能源 → resolve_root 把 x_top 解析成 **REGISTER 根、源=门寄存器**，status=ok、issues=[]，.sv=写 my_gate 断言 x_top 跟随——真源 src_sm 整个不验。块顶虽有一条 ⚠，但文案指错对象（"iddq 门 src_sm 非可 force"）。sim 大概率假红 + 浪费一轮，生成期全绿。
- **护栏**：仅事后 sim 失败；生成期无。
- **建议**：read_dft 解析 E 的条件字母 → 按字母取对应列做门原文（A→列A、B→列B、C→列C）；字母对不上任何非空列 → 记账不猜。

### A3 🔴 read_dft E 形态白名单——变体拼法静默漏门

【实验 E7】`excel_model.py:942-943` 两条正则是唯一入口：

| E 写法 | 结果 |
|---|---|
| `B?0:A` / `B ? 0 : A` | 认门 ✔ |
| `B[0]?0:A`、`(B)?0:A`、`B?0:(A)`、`B?0:A[3:0]`、`B?1:A`、`!B?A:0` | **静默跳过（漏门）** |

- **后果**：门在 RTL 存在但 wb.dft 无此键 → 功能拍不 force iddq（靠 RTL 默认，默认非透传 → 整块假红）、iddq 自检拍消失、输入集与 for_test 金标准失配——正是 R29 mixer2g_trim"少一个源头控制"的复刻，只是这回由拼法触发。
- **护栏**：无（docstring 自称"不乱猜"，但也不吭声）。
- **建议**：E 含 `?` 且含常量支但两条正则都不匹配 → 记入新 `dft_unrecognized` 告警通道（块顶 ⚠ + summary 计数）。这是把"选一条路"换成"loud"的典型点。

### A4 🔴 read_dft 同名两行 last-wins × 改名边 first-wins，互相污染

【实验 E3】`excel_model.py:971` `out[ob]=…`（**last-wins，无告警**）vs `topout.py:116` `out.setdefault`（first-wins）——同一输出名两条带门行（门不同）时：

- E3 实测：`wb.dft['dup_out']` = 第二行的门 other_gate；但 `_dft_rename_edges` 处理第一行时用**全局（=最后一行）的 gate_base** 做排除 → 第一行功能数虚高成 2 → 无边；第二行成为唯一改名边。最终真值表 = 第二行源 s2 × 第二行门，**第一行（s1×iddq）静默不验**，零告警。
- 与 R35 教训直接冲突：regmap 修成 first-wins + `regmap_dups` 告警，dft 两样都没有。
- **建议**：read_dft 改 first-wins + `dft_dups` 通道（复用 `_field_dup_warning` 思路）；`_dft_rename_edges` 的门排除改用**本行自己的 B 列**，不查全局 `wb.dft`。

### A5 🔴 门前/门后网判别 = `_to_dft` 拼法约定（3bde25d 新立的猜）

【推理】`topout.py:254`：源引用带 `_to_dft` = 门前网（不途经兄弟门）；裸名恰撞带门输出 = 门后网（途经门）。

- **触雷条件**：① 设计师笔误少写 `_to_dft`（裸名）而带门兄弟行存在 → 误判门后 → 串门（en_cnt 的反向）；② 写成 `_todft`/`_dft` 等 → 当成另一个基名 → 改名链断 → UNRESOLVED（🟡但记账可见）；③ 万一某设计里**门后网也带 `_to_dft` 拼法** → 漏门。带位宽/大小写已处理（`_strip_width`+lower，验过）。
- **护栏**：三条回归测试锁住三种支形（transp/gated/post-gate），但只锁"约定成立时"的行为。
- **建议**：列入 B 节须 SE 确认清单；确认前对"裸名撞带门输出"的判定加块顶注释记账（当前 note 里有"含 dft 门 %s 作输入"字样，算部分可见）。

### A6 🔴 mux 分支 pin/append 不传 input_bases——iddq 双重 force 冲突

【实验 E4】`topout.py:515-518`（与 `generator.py:1394-1397` build 同口径，故 .sv 同病）：

- **触雷条件**：iddq（RO 网）同时是某 mux 的显式控制/数据输入，且该 mux 输出又被 dft 带门观测。
- **后果（实测）**：每条功能向量既按 assignment force iddq（0/1 扫选路），又被 pin 追加 force iddq=透传值；extra_forces 排在常规驱动**之后**（sv_writer.py:237）→ pin 赢 → "iddq=1 选 case1"的向量实际走 case0 → **断言按 case1 期望必假红**；GUI 真值表 iddq 出现两行。E4 实测同一 .sv 块内出现 `force …iddq=16'h1;` 紧跟 `force …iddq=1'b0;`。
- **护栏**：logic/register 分支有 input_bases 去重，mux 没有——注释自认"与 build 同口径"，即两处一起错。
- **建议**：mux 展开的 bindings/ctrl 基名收集成 input_bases 传入（build 与 topout 同步改，byte-gate 守旧表——无此拓扑的表零影响）。

### A7 🔴 build_index 候选名撞车 setdefault 静默首个

【实验 E5】`topout.py:166-176`：每个 logic/mux 行贡献 3-4 个候选名（out_base/_ls_name/rtl_base/rtl_base_full）。

- **触雷条件**：字面 K=`x_ls` 的行 vs 另一行 `x` 经 level_shift 的 `_ls_name=x_ls`（E5 实测：行序在前者赢，Topout `coll_sig_ls` 解析到 `coll_sig` 的 A?B:C，字面行的 A&B **静默不验**）。同族：K 列重复、rtl_base 带 `_to_logic` 撞字面行。
- **后果**：验错行=假绿（另一行的逻辑无人验，Topout 行还显示 ok）。
- **护栏**：无冲突通道。
- **建议**：build_index 检测"同一候选名被两个不同对象认领" → 记入账目/块顶 ⚠（不必改胜负规则，先可见）。

### A8 🔴 直接命中静默压掉 dft 改名边（同名双源）

【实验 E6】`resolve_root` 优先级 logic>mux>register>桥接：`shadow_top` 既是 logic 行、又是 dft 改名（shadow_src→shadow_top）的输出——直接命中赢，改名边零消费、零告警。R-vco-faston 修了 register 侧撞名（还能改名则续走链），**logic/mux 侧撞名没有对应逻辑**。

- **触雷条件**：SE 复制行/两页各自演化出同名输出（R35 pmu 同款笔误在 dft×logic 之间重演）。
- **后果**：验的是 logic 行，顶层实际由 dft 改名驱动（或反之）→ 假绿方向不可知。
- **建议**：direct 命中后查 `low in _dft_rename_edges` → 命中即块顶 ⚠"本名同时是 dft 改名输出，存在双源"。

### A9 🟡 pin_dft_gate 要求门解析成 RO，否则静默不钉

【推理】`generator.py:794` `b.kind=="RO"` 才 pin；门是 RW 字段/内部信号时 pin 返回 None **无任何记录**（append 侧有 iddq_skipped ⚠，pin 侧没有——功能拍照旧不驱门）。RTL 默认非透传 → 全块假红；默认透传 → 门维度漏验。建议 pin 失败也进 meta。

### A10 🟡 改名指向 mux 源 → 记账不产出（renamed-mux）

【推理】`topout.py:1230-1233`：漏生成但记账可见。真表一旦出现"dft 改名输出、源是 mux 组"即整信号无测试。列入待办即可。

### A11 🟡 Topout 页同名重复行：重复块 + 重复 assert id，dup_labels 不报

【实验 E9】`topout_row_aids`（topout.py:1088-1091）按名字键 last-wins；register 根产出循环无 seen 去重（logic/mux 有 seen_src）。实测同名 3 行 → 3 个块全部 `assert_14_*` → **非法 SV，elaboration 才炸**，且 `dup_labels=[]`。建议：register/renamed 根也过 seen（按 Topout 名）+ row_aids 撞键告警。

### A12 🟡 负向拍不继承门 pin（Topout passthrough 路径）

【实验 E10】`make_negative`（vectors.py:264-300）不拷 extra_forces；`_apply_passthrough_negatives` 在 analyze pin **之后**跑 → 带门 register/改名根的负向拍 extra_forces=[]（实测）。当前被两件事掩住：force 粘滞（前一正向拍的 iddq force 还挂着）+ `[pos,neg,pitch]` 排序不变量。**用户在 GUI 重排向量（负向挪到首位）或未来加 release 即爆**。build 的 logic 路径靠"负向加在 pin 之前"顺序豁免——又一处只靠顺序默契的口径。建议 make_negative 拷贝 extra_forces（与 clone_vector 对齐）。

### A13 🔵 门策略散 6 处（口径漂移的结构性温床）

【推理】同一"这支到底有没有门、门键是谁"的政策现存于：`resolve_root` 直连 register（:227）、桥接 LOGIC/MUX（:263）、桥上撞 register（:285-286）、reg_fallback（:301）、`analyze_signal` logic/mux 兜底（:428/:513）、`_result_gate_info`（:356-358）。逐一核对当前**一致**（含 register 根：RegmapEntry 无 out_base → topo.name 兜底恰与直连集合重合，实验佐证）；唯一现存偏差=analyze 有 input_bases 去重而 _result_gate_info 没有 → 门=显式输入时形态仍标 GATED、per-form 覆盖按 gated 档派发（显示/档位级，无 sim 影响）。3bde25d 已是第三次往这套散置逻辑里加分支。**建议收口成单函数 `gate_obs_for(wb, root, src_obj) -> obs_key|None`，六处全调它**——与 R40"_pick_ref_suffix 中心闸门"同一药方。

## B · 语义模糊清单（纯反向工程、从没让 SE/designer 确认过）

按"值得变 loud"排序：

1. **dft 页 G 列（去向 suffix）的语义与消费**——全仓库无读取点（grep 证实），却是扇出消歧唯一的一手信息（A1/E2）。→ 值得读进来做交叉核对，不一致 loud。
2. **dft 页 E 列字母 ↔ 物理列的对应、"B 列恒=门"**——当前所有表恰好如此，纯排版巧合（A2/E1）。→ 按字母取列 + 对不上 loud。
3. **`_to_dft` 后缀=门前网、裸名撞带门输出=门后网**（3bde25d 新立）——三条测试锁行为，没人确认语义（A5）。→ 问 SE 一句话的事。
4. **dft 同名输出多行**是扇出（合法常态，en_cnt 实证）还是错误？合法时"哪行的门算数"该谁说了算？（A4/E3）→ first-wins+告警最少;理想是按 G 列去向分键。
5. **E=A 恒等行 ~65 个是否有意不门控**——R37 续3 的外部待办至今仍开。漏门方向的系统性存疑。
6. **level_shift 输入网的驱动者**（logic 输出还是 dft 门后输出）——`_apply_level_shift` 按基名巧合绑 logic 行；扇出时决定门归属（A1）。
7. **Topout B 列名与 logic/mux/寄存器同名撞车时谁是真源**（A7/A8/E5/E6）——现状=优先级+行序静默裁决。
8. **iddq 门位宽**——gate_raw 剥宽后恒按 1 bit force；门若是多 bit 字段的某一位，force 全字段/错位无人知。
9. **mux 根的 dft 门与显式输入并存时的期望语义**（A6/E4）——designer 的 for_test 在这种拓扑下长什么样，没见过实例。

## D · 治本 vs 打补丁

### D1 裁判插在哪（scan_rtl 真 nets）

新主线比 R41 时**多了一个现成的插桩点**：R42 的 claims 通道已在 `build_for_topout` 聚齐每个产出块的探针网/force 网/身份/切片（logic/mux 经 G.build、register/renamed 经 `_passthrough_block` 注入圈，四路归一）。所以：

- **阶段一（存在性，最小可行版）**：
  1. `GenOptions.rtl_nets: set[str]|None` + `known_missing_nets`（scan_rtl 导出侧 cf4cc88 已有 Topout+cone 类别，补 missing 负向条目可解析化）。
  2. 校验点放 **claims 聚合处**（`_inject_block_warnings` 内或 build_for_topout 聚合后）：每个 claim 的 `net_base`（叠前缀后的全名与裸名都查）∉ rtl_nets → 块顶 `// ⚠ net-not-in-rtl` + summary `n_rtl_missing` + verifiability 降级；∈ known_missing → 即便配了前缀也降回 needs-prefix（直接治 resolver:365 无条件信任）。
  3. **降级安全**：opts 不配 → 一行不走（逐字节不变，现有 6 sha byte-gate 直接守）。
- **阶段二（门裁判）**：门网 ∈ 该观测输出的 fan-in——需要 scan_rtl 的 assign 扫描（R41 阶段二原样），风险高、须先在公司机验分类正确率。**在此之前，Excel 侧的 G 列交叉核对（A1 建议）就是门归属的穷人裁判**：不用碰 RTL、旧表（G 列空/一致）零影响，先把 E2 这类堵掉。
- **指纹（GATE-2）**：nets.txt 头部写源 Excel 名+sheet 指纹+时间，导入时不符 loud——iddq 假红那轮（stale .sv）已经演示过 stale 文件的代价。

### D2 打补丁（便宜、独立可上，按性价比排序）

1. **read_dft loud 化三件套**（A2/A3/A4）：E 含 `?` 不匹配 → `dft_unrecognized` 记账；同名重复 → first-wins + `dft_dups` 告警；按 E 条件字母取门列。全是读表层改动，旧表（无此形态）逐字节不变。
2. **dft G 列消费 + 兜底门交叉核对**（A1）：杀掉 E2 整族。
3. **门判定收口单函数**（A13）：`gate_obs_for()`，六处调用，配不变量测试。
4. **撞名可见化**（A7/A8/A11）：build_index 冲突告警、direct 命中撞改名边 ⚠、register 根 seen 去重+row_aids 撞键告警。
5. **mux input_bases 去重**（A6）与 **make_negative 拷 extra_forces**（A12）：各一行级修 + byte-gate。

### 被证伪 / 降级的怀疑（如实记录）

1. **"改名链 hops/环护栏会静默丢"**——证伪：reg_fallback / UNRESOLVED 均记账，note 带链路（代码+E8 佐证）。
2. **"两功能输入的 dft 改名行会静默消失"**——证伪：落 UNRESOLVED 记账（E8）。
3. **"_result_gate_info 与 analyze 已经漂移"**——降级：逐分支核对当前一致（含 register 根 RegmapEntry 无 out_base → topo.name 兜底恰与直连集合重合）；唯一偏差是 input_bases 去重仅 analyze 有（形态标注级）。风险是结构性的（6 处散置），不是现行 bug。
4. **"负向丢门 pin 立即假绿"**——降级：机制坐实（E10），但被 force 粘滞 + [pos,neg,pitch] 排序掩住；GUI 重排/未来加 release 才引爆。
5. **门前/门后判别的大小写与位宽拼法**——证伪：`_strip_width`+lower 已处理（E7 佐证边名路径）；真正的暴露面在"少写/异写后缀"（A5）。

### 3bde25d 修法本身的评价

方向正确（链上记账、抑制兜底、三种支形回归测试齐全），但它是在一个**输入已被污染的层**上做精细判别：它依赖的 `wb.dft`（A2/A3/A4 三处猜）和 `_to_dft` 拼法约定（A5）任何一条破，dft_bridged/门前门后判别就在错的数据上"正确地"工作。且它只保护桥接支——同一串门机制在直接命中/_ls 命中支原样存在（A1/E2），修法把门策略的散置点从 5 处加到 6 处（A13）。**兜底本身删不得**（d_en_vco_fc 类靠它），出路不是更聪明的猜，而是给猜配裁判：Excel 侧 G 列交叉核对（便宜）+ rtl_nets 存在性（阶段一）+ fan-in 归属（阶段二）。
