## 0. 三句话

1. **版面按 Design，能力按契约表，逻辑一律走 Qt-free 层**：视图模块里没有一行「算东西」的代码，只有「拿 an/模型 → 画 → 把用户动作转成 state 调用」。
2. **先骨架后皮肤，先 worker 与清单 model**：C0 把后端补齐（全 additive + byte-gate 6/6），C1 落 worker / state / 清单，之后每一波只往骨架上挂视图。
3. **零遗漏靠机械锁**：302 条契约 ID 逐条归属到 21 个模块（附录 A，脚本生成、全覆盖已验），每条测试名含 ID；`contract_check --strict` 全绿是 C5 的闸门。

- **views 之间不互相 import**（`main_view` 组合 `truth.panel` / `sigflow_view` / `sv_preview` 是唯一例外，它是容器）。跨视图通信只有两条线：`state` 的信号（数据变了）和 `bus.netSelected`（当前线网）。

### 1.3 三个选型（判据 + 结论）

**① 清单「点状态 → 行内原因块」怎么做**（三选一：展开行 / 行下方 detail 面板 / delegate 绘制）

| 判据 | 展开行（两级 QTreeView） | 行下方 detail 面板 | delegate 在加高的行里画 |
|---|---|---|---|
| 排序 / 筛选后原因块仍贴着自己那一行 | ✔ 子行随父行走（proxy 递归关闭 + 子行恒接受） | ✔（不在表里） | ✔ |
| 原因块里两个按钮可点、可按 objectName 测 | ✔ `setIndexWidget(子行, ReasonWidget)`，真 QPushButton | ✔ | ✘ 要在 `editorEvent` 里自己算按钮矩形，测试只能发坐标 |
| 版式 = Design「行内」（琥珀左边条、紧贴该行） | ✔ | ✘ 不是行内 | ✔ |
| 多列表头 / 勾选列 / 列宽 / sticky 表头 | ✔ QTreeView 原生 | ✔ | ✔ |
| 实现量 | 中（model 两级 ≈ +120 行） | 小 | 大 |

**结论：两级 `QTreeView`**（`setRootIsDecorated(False)`、`setIndentation(0)`、`setItemsExpandable(False)`，展开只由点状态格触发；子行 `setFirstColumnSpanned`；同一时刻只展开一行，展开时创建 `ReasonWidget` 并 `setIndexWidget`，收起时销毁）。model 是 `QAbstractItemModel`（不是 QAbstractTableModel——任务书写的表格 model 表达不了子行；视觉上它仍是一张表）。

**② 电路图视图路线**（QGraphicsView+QGraphicsSvgItem 直接显示 SVG vs 用 QGraphicsItem 把 `sigflow.Graph` 再画一遍）

| 判据 | A：只显示 SVG | B：Qt 再画一遍 | **C（选定）：SVG 作画面 + Qt-free 布局作命中层** |
|---|---|---|---|
| data-net 命中测试 | ✘ `QSvgRenderer.boundsOnElement(id)` 只给包围盒且要元素 id；折线包围盒盖住半张图 | ✔ 每条边一个 `QGraphicsPathItem`，`shape()` 精确 | ✔ 同 B：命中层是透明 `QGraphicsPathItem`（笔宽 8）/ `QGraphicsRectItem` |
| 点线高亮（hl 样式） | 要重渲染 SVG（≈ms 级，可接受） | 改笔 | 重渲染 `render_svg(graph, highlight_net=net)`（≤60 节点 ≈ 2 ms）后 `renderer.load()` |
| hover 寄存器盒 tooltip | ✘ 没有 hover 目标 | ✔ | ✔ 命中层 rect 的 `hoverEnterEvent` |
| 报告 HTML 与 GUI 的图是否同一份画法 | ✔ 同一 `render_svg` | ✘ 两套画法（17 种图元 × ANSI 形）必漂 | ✔ 同一 `render_svg` |
| 需要后端加元素 id | 需要 | 不需要 | **不需要**（命中层用布局坐标，不用 SVG 元素） |
| 缩放平移 0.3–3× / 1.12 / 光标锚定 / 双击复位 / 右键平移 | ✔ QGraphicsView | ✔ | ✔ |
| 导出 SVG / PNG | ✔ `render_svg` / `render_png` | 要另写 | ✔ 同 A |

**结论：C**。前提是 C0-c 把 `sigflow.render_svg` 的 ①–⑤ 布局段抽成 **Qt-free 的 `sigflow.layout_graph(graph) -> Layout`**（节点 `pos[nid]=(x,y,w,h)`、每条边的折线点列、画布尺寸），`render_svg(graph, title=None, highlight_net=None, layout=None)` 复用它。`boundsOnElement` 不用、SVG 不必加 id。

**③ 后台分析 worker 的粒度**（整表一次 vs 逐信号）：逐信号。`analyze_all` 的循环每信号回调一次（先 `progress` 后 `signalDone`），worker 每信号之间检查取消；清单第一趟由 `skeleton_models()`（只 `resolve_root`）秒出。见 §2.2 与 §4 N8。

### 2.2 后台分析 worker `ui/worker.py`

```python
class AnalysisWorker(QObject):
    started   = Signal(str, int)          # view_id, total
    progress  = Signal(int, int, str)     # done, total, name
    signalDone = Signal(str, dict)        # name, lite_model
    finished  = Signal(str, list)         # view_id, models(full 或 lite)
    cancelled = Signal(str, list)         # view_id, models_partial
    failed    = Signal(str, str)          # view_id, message（已 scrub）

    def start(self, provider, request: contracts.AnalysisRequest, engine_lock) -> None
    def cancel(self) -> None              # 置 threading.Event；下一信号边界生效
    def is_running(self) -> bool
```

运行规则（唯一写法）：
1. `start` 前主线程先 `models = provider.skeleton_models()` → `state.set_models(vid, models, partial=True)`（每行 `status="pending"`、`status_detail="pending"`、`n_vectors=None`）——清单立刻可点。
2. 线程里：`provider.view_models(mode, max_tests, exhaustive, sig_cov, form_cov, progress=cb, should_cancel=ev.is_set, lite=True)`；`cb(done, total, name, lite)`：先 `progress.emit(done,total,name)`，`lite` 非 None 时 `signalDone.emit(name, lite)`。每个信号的分析在 `with engine_lock:` 内（provider 内部实现，见 §4 N8），信号之间释放锁 → 主线程 `state.analyze(当前信号)` 能插进来。
3. 正常结束 `finished(vid, models)`；取消 `cancelled(vid, models_partial)`；异常 `failed(vid, msg)`（C-043：app 在详情区写「分析失败（已捕获，未崩）」+ 原因）。
4. 同一时刻只跑一个 job；换范围 / 改覆盖度 → 先 `cancel()` 再 `start()`；指纹没变不重跑（C-265）。
5. 取消后已完成的模型保留（`state.set_models(partial=True)` 只覆盖回填过的行）。

### 2.3 清单 model 列与 roles

`contracts.ListCol`（11 列）/ `LIST_DEFAULT_VISIBLE`（勾选 · 反例 · 信号 · 状态 · 用例 · owner）/ `LIST_OPTIONAL`（断言号 · 分类 · 逻辑类型 · 探针前缀 · 表达式）/ `ListRole`（14 个）。RTL 补充标记不是列：`NAME` 列的 `DecorationRole` 给琥珀圆点、`ToolTipRole` 给理由（C-039/C-215）。子行（原因行）只有 `IS_REASON_ROW=True` + `REASON`，其余 role 返回 None；`flags` = 不可选中、不可勾。


## 8. 风险与未决（只列真未决）

1. **C-288 / C-289（覆盖度叠加、多信号总览+PDF）已拍板排到 v2 之后，但契约表类别是「新增」**——`contract_check --strict` 会报未覆盖。需主控二选一：把两条类别改成「删除」并在 note 写「v2 之后单开任务」；或给 `contract_check` 加「延期」类别（`EXEMPT` 扩展）。本文按前者写 §7.4 的 292。 **主控裁决（B4）：取后者——契约表加「延期」类别，`tools/contract_check.py` 的免检集 = {删除, 延期}，C-288/C-289 已改为延期。**
2. **§7-2 八档状态的判据来源**：`spec-collision` / `false-green` 现在只在 `generator` 的 mux 分析 meta 里（`value_collision` / `ctrl_mismatch_rows`），logic 路径没有同名结构；C0-a 若发现某档在 `res.meta/issues` 里没有结构化判据，只能标 `clean` + 保留 issues 原文（不猜）。这会让 Design D 数组「⚠ 字段太窄·假绿」这类标签在部分信号上退化成 issues 文本——需要 C0-a 回报实际能覆盖的档数。
3. **N8 的 `report_for_topout` 第二趟**：`lite=True` 跳过联表后，清单模型不再有 `tests/inputs/chain`，任何仍读这三个键的地方（`gui.py` 旧视图、报告）走 `lite=False`；若有测试直接比对 `topout_view_models` 输出，`lite=False` 必须逐键相同（C0-a 已列为验收）。
4. **worker 与主线程共用 wb 的互斥**：`engine_lock` 是逐信号粒度；`_supplemented()` 与 `Resolver.__init__` 回写 `wb.logic[*]._append_to_logic` 都在锁内。风险是 mux 分析里对 `wb` 的其它隐式写（`build_index` 缓存 `wb._index_collisions`）——锁内即安全，但 C1-a 需要一条压力测试（worker 跑 wl 时主线程连点 21 个信号）来证明。
5. **offscreen 缺中文字体**：截图断言只看版面（尺寸/相对位置），文字一律 `widget.text()`；`QFontDatabase` 无微软雅黑时回退 `FONT_UI_FALLBACKS`，不影响测试。
6. **QTreeView + `setIndexWidget` 在 proxy 排序后的稳定性**：只允许一行展开且每次排序前 `set_expanded(None)`（C1-b 实现约束），如实测仍有残影则改为收起后重建——已在简报里写成唯一写法，风险归零，但要 C1-b 用 `test_c037_sort_keeps_reason_row_attached` 证明。
7. **HTML 报告基线的落点**：主控已实证——`tests/test_sigflow.py:673/686/721` 只断 `attach_report_svgs` 的张数与 crash-proof，**没有字节基线**；C0-c 只需保证这些测试仍绿，无需重录。
8. **N2 的 `_pos/_neg` 汇总块后缀**：主控已实证——`topout.py` 全文无 `block_suffix`（旧 `gui.on_generate` 经 `generator.render(block_suffix=)` 才有）；C0-b 按 §4.2 加 `options["block_suffix"]` 透传（默认空 = 字节不变）。
9. **分层线（I-19）的判据定版：引擎与旧门面一律禁，Qt-free 层按显式白名单准入。** —— **主控裁决（C2-int）**，起因是 `coverage.py` 要 `session.FORM_COV_ROWS`（§6.5 明写的三层覆盖度判据）、`side_panel.py` 要 `inputs_table.input_rows` / `analysis_norm.subst_expr`，照 §1.2 那句「views 只准 import state/bus/…」字面读会把这两条判成违规，而真把判据抄进视图才是真的违规（同一口径两份，必漂）。
   **定版**：`tests/test_ui_c1_integration.py::test_ui_layering` 分两段判 ——
   ① **引擎模块**（`topout` `pageviews` `sigflow` `generator` `resolver` `vectors` `mux_gen` `cone` `sv_writer`）与**旧门面**（`gui` `legacy_gui`）一律禁，唯一例外仍是 `sigflow_view.py → sigflow` 的**渲染**三个函数（`layout_graph` / `render_svg` / `render_png`，架构 §1.3②）；
   ② **Qt-free 层**（`session` `edits` `inputs_table` `analysis_norm` `exports` `providers` `truth_edit` `excel_model`）按 `QTFREE_ALLOWED` 这张 **{ui 文件: {模块: 为什么}}** 的白名单逐条准入 —— 白名单以**实际 import** 为准，每条写一句理由；有 import 没登记报红，登记了没人 import 也报红（`test_ui_layering_whitelist_has_no_dead_entries`）。
   `excel_model` 在 §1.1 的表里挂在引擎那一行，但它实际是纯数据模型（`load_workbook` / `_strip_width`，无 Qt、无分析），按 Qt-free 白名单管：只有 `state.py`（唯一持有 wb 的地方）与 `bus.py`（线网比对键剥位宽）两条。
   这样写的用意：「允许 Qt-free」不会一路滑成「什么都能 import」—— 每加一条依赖都要当场说清为什么，代价是一行白名单，收益是这条线以后还判得动。
