# 任务：为一个桌面工具设计 v2 界面（信息架构 + 关键界面 + 组件规范 + 旧→新映射表）

## 1. 这个工具是什么

Dreg_verify 是一个 Windows 桌面工具（Python + PySide6/Qt，离线、单窗口、中文界面），给芯片数字验证工程师用。
芯片里有一块「寄存器控制逻辑」（Dreg）：软件往寄存器写值，经过一串组合逻辑（与/或/非、选择器 mux、DFT 门控），变成几百根顶层输出信号去控制模拟电路。设计规格写在一份 Excel 里（十几页：寄存器地址表、logic 页真值表达式、mux 页 N 选 1、dft/iddq 门控页、Topout 页=要验证的顶层信号清单）。
工具做的事：读 Excel → 对每个顶层信号，从输出往回展开到源寄存器（我们叫 cone 展开，界面上不许出现这个词）→ 生成测试向量和真值表 → 输出 SystemVerilog 断言文件 .sv（每条测试 = 先写寄存器/force 线网，再断言顶层信号等于期望值）→ 工程师把 .sv 拿到隔离网络（红区 Linux）的仿真环境跑。仿真只会回两种结果：断言过/不过，或者「找不到这根网」（elaboration 失败，错误码 CUVUNF）。

## 2. 用户是谁，在干什么

用户 = Dreg 验证工程师（IC 数字验证背景，天天写 SystemVerilog，读得懂 `RF_WRITE(10'h64, 16'h2)`、`force ENV_RF.xxx`、`assert`、地址/位段、RO/RW、iddq、DFT），不是软件开发者。一张表 200+ 个顶层信号，按 owner 分给几个人。他们用这个工具的一次典型工作：
1. 载入 Excel，看这张表要验哪些信号、哪些工具建得出来、哪些建不出（以及为什么）。
2. 逐个信号看逻辑对不对：从寄存器到顶层口中间经过什么；每条测试写哪个地址哪几位、force 哪根线、探哪根线；期望值是多少。
3. 该手填期望的手填（规格 designer 独立给值，避免「用表达式算的值去验表达式」的自证）；加几条故意填错的反例，验证 checker 真能抓错。
4. 导出交付物：.sv（正向/反例）、给人看的报告（HTML/CSV/Excel）、回填 for_test 页给 designer、nets.txt 给红区做网名扫描、claims.json 给红区的比对脚本、整份配置（给同事/换机器）。
5. 仿真回来报「找不到网」→ 回到工具诊断：导出 nets.txt → 红区跑扫描脚本 → 把扫出来的层级前缀导回工具 → 重新导出。其它诊断动作：规格缺了一级逻辑就手工补一段等价表达式；两个东西撞名了就强制直接 force 顶层网；覆盖度不够就调档。

## 3. 用户的第一性问题（界面必须按这个顺序回答）

Q1 **我要验什么？** 清单 + 每个信号的状态（可建 / 有问题 / 跳过）+ 跳过或有问题的**名字和原因**（不是数量）。
Q2 **这个信号的逻辑长什么样？** 工程师认电路图和真实信号名，不认 A/B/C 字母。要三视合一：文字展开链（每层：Excel 原式 = 代入真名）、门级电路图（新）、真值表（行=输入/输出信号，列=测试）。三处指的是同一批线网，选中一根要联动高亮。
Q3 **每条测试到底驱动了什么、探了什么，名字可信吗？** 输入信号表（字母 → 真名 · 角色(控制位/数据位/门控) · RO/RW · 驱动方式 `RF_WRITE 0x64 bit<<0` 或 `force ENV_RF.d_xxx`）必须是一等公民，不能只藏在 tooltip。线网名有两种来源：表里查到的（可信）vs 工具按命名约定猜的（不可信，仿真最容易报找不到）——所有显示线网名的地方都要区分。
Q4 **期望值是谁给的？** 程序算的（auto）还是 designer 手填的；手填进度 N/M；一键「auto→期望」等于放弃独立核对，必须二次确认并在表上留痕。要有批量填/导入期望的通道（现在一个信号 25 列、一张表上百次单元格编辑）。
Q5 **交付什么、漏了什么？** 一个导出中心列全 6 种交付物，每种可选范围（全部/勾选/仅正向/仅反例）；导完必须点名跳过了哪些信号、为什么。
Q6 **出了问题怎么修？** 诊断动作按「症状 → 步骤」组织，例如「仿真报找不到网？三步：导 nets.txt → 红区跑 scan_rtl.py → 导入 probe_prefixes.txt」，而不是一排孤立按钮。

## 4. 现状与痛点（v1，见附图）

- 6 个顶层 tab：「Topout 视图」（默认）+「logic/mux/dft/iddq 视图」（同一个控件的 4 个复制品，只是数据范围换成某一页本地、不跨页）+「排查(旧)」（一套完全独立的旧实现，4900 行）。
- 约 227 个可交互控件，其中约 110 个按钮是 5 个 tab 逐字重复的同一套；「覆盖度」这一件事界面上同时有 5 个下拉、2 套模型；真值表编辑有 2 套实现 24 个按钮；两个「导出 .sv 选项」对话框默认值不同却共用设置。
- 新门面缺旧门面有的关键东西：输入信号表、每列驱动明细、点信号看解析明细、按列排序、预览本信号 .sv、确认框、列名校验、单列 mux 数据、强制 force、导出/导入配置入口。旧门面有 6 组开关在新门面根本不生效也不提示。
- 默认版面 1600px 宽时，信号表最重要的「状态」「用例」两列在横向滚动条后面。
- 反馈全是数字：「信号 12，断言块 11，测试用例 115，记账 1」——不点名、不说原因。
- 术语裸露：cone、F0–F4、prefixed-wire、wire 兜底、记账、tmm、regmap、CUVUNF 在界面上出现却没有解释；R/K/top/type 直接暴露 Excel 列字母。
- claims.json 这种红区必需的交付物在 GUI 里没有出口。

## 5. 我们的假设（欢迎推翻，但要给理由）

H1 6 tab → **1 个工作台**：左清单 + 右详情。「Topout 全链 / 只看 logic 页 / 只看 mux 页 / dft / iddq」是清单的**范围**筛选，不是 tab。
H2 详情 = **三视合一**（展开链 · 电路图 · 真值表）+ 输入信号表常驻 + .sv 预览（本信号），共享一个「当前线网」高亮。
H3 覆盖度三层（全局默认 → 按逻辑类型 → 本信号）**塌成一个控件**：平时只显示「本信号生效档 = 全面（来自：逻辑类型·选路）」，点开才见三层。
H4 **导出中心**一个入口，6 种交付物一张表：交付物 | 范围 | 选项 | 上次导出到哪。完成反馈 = 跳过项列表（名字 + 原因）在前，计数在后。
H5 **诊断抽屉**：探针前缀 / 强制 force / RTL 补充逻辑 / nets.txt / 缺前缀是否强制生成，按症状组织；平时收起。
H6 真值表编辑要做到 **spreadsheet 级**（已拍板为必需，不是可选）：像 Excel 一样多格选区、TSV 粘贴落在活动格、粘贴超出行数自动追加、整次粘贴一个撤销步、从 CSV/xlsx 导入期望、冻结左侧信号名列和表头、右键行列菜单、放大到接近全屏的编辑覆盖层、手填进度 N/M、当前列高亮、Ctrl+D 复制列、重命名校验、清零/删反例/auto→期望 三处确认。

## 6. 新组件：信号流门级电路图（必须设计）

每个信号一张图，源寄存器在左、顶层输出在右，中间是门级图元，每条线标真实线网名 + 位宽 `[3:0]`：
- 图元：寄存器盒（名 / `RW @0x2d[4:4]`）、线控/RO 输入盒（`RO force <网名>`）、猜名输入盒（虚线框 + 角标「名字来自命名约定，表里未查到」）、AND/OR/NOT/XOR/NAND、MUX2、MUXn（每支标 case 值，含 don't-care 如 `4'b000x`，冲突支红色虚线 + Excel 行号）、DFT 门控盒（`iddq ? 0 : x`）、总线抽头/合并（切片 `[1:1]`、拼接）、改名/电平移位透传块（左源名右顶层口名）、顶层输出端子。
- 交互：点一根线 → 展开链/真值表里同名行联动高亮；hover 寄存器盒 → 地址/位段/为什么判成 RO 或 RW；可缩放平移；导出 SVG/PNG（同一张图也会内联进 HTML 报告）。
- 二期叠加（预留视觉空间）：把当前测试向量实际走到的 mux 支「点亮」，从没被驱动过的支涂灰。
- 深度：最深 6 层、最多约 60 个节点、宽总线粗线不按位展开。要设计小图（1 个寄存器直连顶层）和大图（3 级 mux 级联 + 门控）两种状态。

## 8. 设计原则（用户明确要求过，违反即返工）

1. 面向 IC 验证工程师，不面向工具开发者：不出现仓库路径、git、CLI 命令、"请把下面发给维护者"。
2. 跳过/过滤的内容必须可见：名字 + 原因 > 数量。
3. 编辑器不自动塞模板行；可复用配置都能导入/导出。
4. 说明文案用工程师的语言，给真实层级路径示例（如「信号实际在 ENV_RF.U_BT_LP_PLL_DIG.pll_n → 前缀填 U_BT_LP_PLL_DIG」）。
5. 真值表行表头直接用真实信号名；字母↔信号对照放输入信号表和 tooltip。任何「内部坐标 vs 真名」的取舍默认显示真名。
6. 允许直接用的词：ENV_RF、force、RF_WRITE、断言、RO/RW、地址、位段、iddq、DFT、mux、case、探针、层级前缀、for_test、nets.txt。禁止裸用（要么换词要么就地解释）：cone、F0–F4、缝、prefixed-wire、wire 兜底、记账、claims、tmm、regmap、CUVUNF（首次出现要展开成「仿真器找不到这根网」）。
7. 密集数字表格是核心界面，不要为了留白牺牲信息密度；但默认可见列必须包含 状态 和 用例。

## 9. 约束

- 已拍板：旧『排查(旧)』标签在 v2 验收后直接删除，不并存；电路图随 v2 一起出；claims.json 进导出中心；期望手填与批量导入为必需。
- 桌面 Qt 应用，单窗口，浅色主题；最小 1366×768，常用 1920×1080；键盘快捷键（Ctrl+O/L/P/R/G/D 已有习惯）。
- 离线、无 web、无外部字体；中文界面，表格里的信号名和数值等宽字体。
- 不改数据层算法；不做多窗口；不做移动端。
- 现有全部能力一个都不能丢（清单见 §10），只能换位置或合并。
