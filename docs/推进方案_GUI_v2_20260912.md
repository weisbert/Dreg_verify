## 0. 结论

1. **「两个版本混杂」只剩 GUI 层。** 数据层已在 6 月的 S0→S3 收敛成一套引擎（`generator.build` 出 .sv，`topout.analyze_signal` 供显示，S2 已把二者对齐，byte-gate 6 sha 守着），剩 1 个 xfail 架构债。真正并存的是 `gui.py` 里两套门面：新 `SignalView`×5 实例 + 旧『排查(旧)』4900 行。所以重构对象是 GUI，不是全项目 —— Claude Design 的 scope 要收在这里。
2. **旧有新无的真值表能力确实存在，而且比 6 月审计认定的多。** 6 月补回的是持久化/导出/配置这类外围；真值表内部的「驱动明细整族」「数值格式」「确认框」「校验」「单列 mux 数据」「预览本信号」「排序」「强制 force 后端」没搬，另有 2 个实测 bug（批量加负向列名全撞；mux 数据值编辑后所见≠所得）。清单见 §4。
3. **信号流门级图可行、便宜、不碰核心。** 仓库改动 4 行（子树根挂 `origin_net`），新模块 `sigflow.py` 纯函数 + 自写 SVG，一份渲染器同时进 GUI / HTML 报告 / ppt。mux 根走结构路线兜底（WL 15 组 mux 有 5 组根本没有 AST）。
4. **推进顺序 = 三条轨并行，一个里程碑收口**（§3）。止血和信号流图不等 Design；GUI v2 等 Design 回来再动手，但能力契约（§4）现在就定，它同时是 Design 的输入和 v2 的验收单。

## 2. 判断

- **不在现 SignalView 上逐项打补丁。** 它和 legacy 已经是两套代码，再补一遍等于第三套。真值表编辑层的修复只做「模型层」的（§3 轨 0），让它自然被 v2 继承。
- **v2 的 GUI 代码换包不换引擎。** `dreg_verify/ui/` 新包、分文件、纯 view；数据模型就是现有 `_TopoutProvider/_PageProvider` 的 analyze 结果 + edits 层，不重写。`gui.py` 保留到能力契约全绿再删。
- **6 tab → 1 工作台** 是我们给 Design 的假设（允许推翻）：四个页本地视图是同一张清单的「范围」筛选，不是四个 tab；排查(旧) 里仍有价值的东西全部收进「诊断」抽屉。
- **信号流图先做数据层和 SVG**，挂进现 GUI 一个子页只是为了立刻可用；它在 v2 里的位置由 Design 定（详情页三视合一之一）。

## 3. 三条轨 + 里程碑

### 轨 0「止血」—— 现在就做，opus，1 轮，不等 Design
全部是编辑层/后端修复，v1 v2 通吃：
1. bug①：`_e_addneg` 列名生成查不到 `U0_NEG` → 全撞；同一次给负向列再加负向。改 `_new_col_name` 查全集 + 只对正向列造负向 + 去重「同输入已有负向」。
2. bug②：`_set_mux_data` 走 `_load_signal` 冻结 cols → 编辑过的 mux 信号所见≠所得。
3. `_parse_cell_int` 接管 legacy `_parse_int` 的 8 种写法（`16'h3 / 'b101 / 'd9 / hA`），解析失败必须可见（状态栏 + 单元格还原）。
4. 三处确认框：清零 / 删负向（含手调错值） / auto→期望（"采信表达式=失去独立核对意义"）。
5. `_e_rename_col` 接 `_sanitize_name` + 拒 `T<n>` + 查重。
6. `force_overrides` 接进 Topout/页视图后端（topout.py:1278/1540/1636、pageviews.py:59 建 Resolver 处 + 1306 GenOptions），入口先复用现有对话框。
7. 修级联说明窗找错路径（`docs/级联模式说明.md`），删 6 处 tooltip 里的 CLI 命令。
护栏：880 测试绿 + byte-gate 6 sha 不变（1–6 都不该动 .sv 字节，7 不碰数据层）。每项带测试。

### 轨 1「信号流图 MVP」—— 现在就做，opus，1–2 轮，与轨 0 并行（文件不重叠）

## 4. 能力契约（v2 不能丢的东西）

来源：审计 A 的 Top10 + 次要项、清单 B 的全量控件、6 月已补回项、用户 2026-06-23 GUI 冗余审查已定方向。四类：

### 4.1 必保留（现在两边都有或只在一边有）
- 载表；信号清单（勾选/负向勾选/信号名带切片/断言号/owner/分类/逻辑类型/状态/探针前缀/用例）；**按列排序**；owner 多选 / 分类 / 状态 / 正则搜索；全选/清空/勾选选中行；全部加负向/清除负向；勾选持久化。
- 详情：展开链（原式 + 真名代入）；**输入信号表（字母→真名·角色·RO/RW·驱动 `RF_WRITE 0x64 bit<<0` / `force ENV_RF.x`）**；**每列 force/RF_WRITE 明细**（tooltip 或面板）；**点信号看解析明细 + CUVUNF 排查提示**；状态解释（STATUS_HELP 8 档）；RTL 补充信号琥珀标记与横幅。
- 真值表：重新生成 / 加列 / 复制列(Ctrl+D) / 删列 / 清零(确认) / 重命名(校验) / auto→期望(确认) / 加负向(选中，去重) / 全部用例加负向 / 删负向(确认) / 逐格改输入与期望 / 8 种数值写法 / mux 数据值整表 + **单列** 手填 / mux 错值==正确值保护 / 期望手填进度 N/M / 当前列高亮 / 列宽保留 / 单信号 CSV（含 期望(bin)/force/RF_WRITE 三行）/ **预览本信号 .sv**。
- 覆盖度：全局默认 / 按逻辑类型 F0–F4 / 本信号 三层 + 上限 + 穷举；三层塌成一个控件显示「生效档 + 来源」。
- 导出：.sv（范围 全部/仅正向/仅负向、注释、末尾汇总、owner）+ 重复标号确认 + **跳过项点名+原因**；报告 HTML/CSV/**Excel**（扩展名纠正 + 完成计数）；回填 for_test（防覆盖源表 + 组数）；nets.txt 按类别；**claims.json（新增 GUI 出口）**；**导出/导入配置**（全局入口）。
- 诊断：探针前缀映射（导入/导出）；**强制 force 信号（入口 + Topout 后端接通）**；RTL 补充逻辑（JSON 编辑 + 模板 + 导入）；覆盖度算法说明；级联/cone 说明（修路径）。
- 四个页本地视图的能力（只看本页输入输出、不跨页）作为「范围」保留。

### 4.2 合并
- 5 份 SignalView 工具条 → 1 份；两个『导出 .sv 选项』→ 1 个（统一默认值与 settings 键）；两套真值表编辑器 → 1 套；两套覆盖度模型 → 1 套；`.sv 预览` 两处 → 1 处。

### 4.3 降级进「诊断」抽屉（逃生阀，不当主力）
- 探针前缀 / 强制 force / include_risky（缺前缀强制生成，现 Topout 写死 True → 改成可见开关）/ RTL 补充逻辑 / nets.txt 导出 / 页本地范围。

### 4.4 删除（用户 2026-06-23 已定方向，Topout 模型下无意义）
- 『仅 top_output=1』筛（真表 N 列全 0）；尾缀三件套（logic 加尾缀 / mux 加尾缀 / 本信号探尾缀网）；级联「force 级联网」模式与 logic/mux/本信号三处级联下拉（Topout cone 展到底永不 force 中间网）；R/K/top/type 列头直接暴露 Excel 列字母。
- 删前用真表确认一次这些开关在 Topout 路径上确实不被后端读取（清单 B 已证 `_TopoutProvider` 不传，但要防 CLI 旧路径依赖）。
