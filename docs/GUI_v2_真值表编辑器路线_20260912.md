# 真值表编辑器技术 spike — 结论

> 来源：GUI v2 执行计划 Phase A5（2026-09-12，opus spike）。原型代码与 22 条 offscreen 测试留在本地 spike 目录，不入库；本文是给 Phase B3 架构步的输入。
> 主控裁决：采用路线 A（QTableView + QAbstractTableModel 原生），拍板 #2 默认值经实证确认。


**日期** 2026-09-12 ／ **性质** 技术 spike，产物全部在 本地 spike 目录，**未动仓库一个字节、未 commit**
**环境** `C:/code/Dreg_verify/.venv/Scripts/python.exe`（Python 3.13.7 + PySide6 6.11.1），`QT_QPA_PLATFORM=offscreen`
**目标** 为 GUI v2 的「spreadsheet 级真值表编辑器」在两条路线里选一条：
A = QTableView + QAbstractTableModel 原生；B = QWebEngineView 内嵌 vendored jspreadsheet

---

## 0. 一句话结论

> **走路线 A（QTableView 原生）。** 12 项验收全部做到、全部有自动化测试、5 轮重跑零 flake，
> 冷启动 **0.17 s**、**零新增依赖**；路线 B 在「整次粘贴 = 一个撤销步」和「按业务状态上色」
> 这两项上**结构性做不到**（两套互不相通的撤销栈；颜色要 Python 每次重算全表 CSS 再推），
> 还要背 **319 MB** Chromium 和 0.82 s 冷启动。主控「默认倾向 QTableView 原生」的判断，**证据支持，予以确认**。

**决定性的是这 4 项**（不是 12 项平权）：#3 撤销粒度、#2 粘贴方向（超行拒绝）、#9 状态色、#10 数值写法校验失败还原。
其余 8 项两条路线都能做，只是代码量不同——不构成选型理由。

| | A | B |
|---|---|---|

| 整套耗时 | **1.9 s**（≈160 ms/条） | 3.6 s（≈360 ms/条） |
| 5/3 轮重跑 | **5/5 全绿，零 flake** | 3/3 全绿（**但见下面「怎么写才不 flake」**） |

**B 的测试有 3 个必须先踩过才写得对的坑**（写在 `test_proto_web.py` 注释里）：

1. **`loadFinished` 之后立刻 `pushData` 会丢**——JS 侧 `new QWebChannel()` 的回调比 `loadFinished` 晚 ~50 ms。必须让 JS 主动 `onBoot()` 回叫 Python，Python 再推数据。第一版就栽在这，表现是「一直不就绪」，没有任何报错。
2. **等待条件里不能调 `runJavaScript`**——它在 `processEvents()` 里再开一层 `QEventLoop`，回调投递不回来，条件永远为假（表现为 8 s 超时后拿到 `None`）。等待只能用 Python 侧便宜的条件（bridge 收到的回调计数）。
3. **JS 挂了没有任何 Python 侧信号**——必须自己 override `QWebEnginePage.javaScriptConsoleMessage` 把 console 捞回来，否则 `jspreadsheet()` 抛异常只表现成「页面空白 + 一直不就绪」。

A 侧只踩到 1 个：`QTest.mouseMove` 在 Qt6 里不带 buttons 状态，拖不出橡皮筋选区，要自己造 `QMouseEvent`（仍走 widget 的公共事件入口，不是调内部方法）。已封装在 `conftest.drag()`，6 行。

## 3. 路线 B 的额外发现（都是实测，不是查文档）

* **许可证 OK**：`jspreadsheet.js` 里 `version={version:"5.0.0", license:"MIT", …}`、字符串 `Jspreadsheet CE`。CE 版 MIT，可以 vendored。
* **Report 仓里那份是 v5，API 与 v4 不兼容**：必须 `jspreadsheet(el, {worksheets:[options], …spreadsheet级设置})`，v4 的顶层 `data/columns` 会抛 `JSS: worksheets are not defined`——而且是 **`Uncaught (in promise)`，同步 `try/catch` 抓不到**。返回值是 spreadsheet，`[0]` 才是 worksheet。
* **`onbeforepaste` 在 v5 的签名是 `(worksheet, data2d, x, y)`**，`data2d` 是 `[[{value},…],…]` 的二维数组，不是 v4 的 TSV 字符串。按 v4 签名写会静默失效。
* **数据形状会漂**：手敲进去的格子 `getValueFromCoords` 返回**裸字符串**，粘贴进去的返回 **`{value:"…"}` 对象**。任何读值的地方都得自己 unwrap（`test_w4e` 里断言了这一点）。
* **`parseFormulas:false` 必须显式关**（Report 仓踩过并留了注释）：`=` 开头的格子会被当公式、算不出来就显示 `#ERROR`。IC 真值表里 `=` 是数据。
* **`sheet.fullscreen` 在 CE 5.0.0 不存在**（探测 `typeof` 得 `undefined`），#6 放大层没有原生可用。
* CE 原生**有**的（实测 `typeof === 'function'`）：`undo redo copy paste insertColumn deleteColumn getSelected getSelection setStyle getStyle setValueFromCoords getData setHeader setWidth hideColumn showColumn search orderBy download`。

## 4. 推荐：**路线 A**，理由与剩余风险

### 理由（按权重）

1. **撤销语义是这个编辑器的命门，B 给不了。** 期望值是要进 `.sv` 断言的东西，「粘错了一把 Ctrl+Z 回去」必须是**一次**、必须把追加的列一起收回。A 用 `QUndoStack.beginMacro` 天然做到（`test_03` 断言了 `undo.index()` 只 +1、撤销后列数回到原值）；B 里粘贴一旦追加列就是 2 步，而且**改名/加反例/导入期望这些 Python 侧动作根本不在 jspreadsheet 的 history 里**——用户会遇到「Ctrl+Z 撤销的不是我刚做的那件事」。这是没法绕的。
2. **状态色是这个表的信息主体，不是装饰。** 绿/红/琥珀/淡紫/灰字承载「designer 审过没有、跟表达式一致不一致、是不是反例」。A 里它是 `data(role=BackgroundRole)` 的一次分支判断，改一格自动重绘；B 里它是「Python 重算全表 720 条 CSS → JSON → JS → `setStyle`」，每次编辑一轮，而且列坐标要换算成 A/B/C 字母。
3. **数值写法校验必须同步。** `truth_edit.parse_int` 的 8 种写法 + 「失败绝不静默吞成 0」是已经用教训换来的口径（`_parse_failed` 的注释写着「那会让『输入格变 0、期望格变未填』悄悄改掉验证意图」）。A 里 `setData` 返回 `False`，Qt 当场还原、零闪跳；B 里校验在 Python、编辑在 JS，只能让脏值先落地再异步推回。
4. **零依赖 vs 319 MB。** 用户在公司机上跑，`ppt/` 都要绕着走，多背一个 Chromium 是纯负担。冷启动 0.17 s vs 0.82 s 也是每次开表都付的。
5. **测试成本反了过来。** 直觉是「web 好测」，实测是 A 每条测试 160 ms、真键鼠直接打；B 每条 360 ms、还要先踩三个异步坑才写得对。

### 剩余风险（A 的，都有缓解）

| 风险 | 缓解 |
|---|---|
| `QTableView` 没有**填充柄**（拖右下角复制）和**跨表拖拽** | IC 场景用 Ctrl+D 复制整列更贴切；填充柄真要，`TruthTableView` 里 ~40 行画个小方块 + 拖拽即可，不阻塞 C3 |
| 大表列宽自适应的手感要自己调 | 已验证「只给**新插入**的列 `resizeColumnToContents`，老列不动」就不弹回（`test_08`） |
| 键位用 `keyPressEvent` 而非 `QAction` 的 shortcut（为了 offscreen 可测） | 产品里两者都挂：菜单项显示快捷键用 `QAction`（`Qt.WidgetWithChildrenShortcut`），实际处理仍在 `keyPressEvent`，测试打的是后者 |
| 冻结列用的是「双视图并排 + 滚动条同步」，不是 Qt 官方示例的 overlay | 并排更稳（不用管 `stackUnder`/几何跟随），代价是选区不跨越信号名列——而信号名本来就不该被选中编辑 |
| 6 态色 + 隔行底色叠加后的可读性 | 沿用 gui.py 已在用的同一批颜色值，已验证过 |

## 5. 给架构步：v2 的 model 应该暴露的接口

`proto_qt.TruthModel` 已经是按这份清单写的，可以直接当契约抄。

### 信号

| 信号 | 何时发 | 谁接 |
|---|---|---|
| `parseFailed(str)` | 数值写法没认出来（已还原旧值） | 状态栏 |
| `pasteReport(str)` | 一次粘贴的结果说明（落了几格、新增哪些列、**跳过哪些行及原因**） | 状态栏 / 提示条 |
| `progressChanged(int n, int m)` | 期望手填进度变化 | 状态栏常驻标签 |
| `dataChanged` / `headerDataChanged` / `rowsInserted` / `columnsInserted` / `columnsRemoved` | Qt 标准 | 视图、冻结列视图、预览/`.sv` 重生成 |

### 方法

```python
# ── 形状 ──
row_kind(r) -> "input" | "auto" | "exp"      # 行语义，view 不要自己按下标判断
row_label(r) -> str                           # 带位宽切片的信号名
all_names() -> [str]                          # 全部测试列的最终标号（含 _NEG）

# ── 列操作（都走 beginInsert/RemoveColumns，视图自动跟）──
append_test_column(n=1, src_idx=None, prefix="U") -> [新列名]   # 命名唯一性走 TE.uniq_col_name（查全集）
duplicate_column(c) -> (新下标, 新列名)
remove_column(c) -> 被删的列 dict            # 供 undo 还原
rename_column(c, new_name) -> (ok, 最终名 | 失败原因)            # 走 TE.check_col_name 三道关
add_negative(c) -> (造了几条, 跳过几条)       # 走 TE.plan_negatives，负向不套娃
set_highlight_col(c)                          # 当前列高亮，只重绘一进一出两列

# ── 数据 ──
setData(index, value)  -> bool                # **唯一**写入口，内部 push 到 QUndoStack；False = 已还原
copy_tsv(indexes) -> str
paste_tsv(text, r0, c0) -> (ok, 给用户看的提示文本)
import_expectations(path) -> (落了几列, [没对上的列名], 提示文本)   # CSV/xlsx 同一入口
fill_progress() -> (n, m)

# ── 自定义 role（view/delegate 只认 role，不认业务）──
Qt.BackgroundRole   → 8 态底色       IsFallbackRole → 这格是不是兜底值（灰斜体）
Qt.ForegroundRole   → 灰字/只读字色   RowKindRole    → 行语义
Qt.FontRole         → 控制位/期望行加粗  ColStateRole → "auto"|"user"|"neg"|"dft"
```

**两条必须写进架构约束的**：

1. **唯一写入口是 `setData`**，它 push `QUndoStack`。任何「不经 undo 直接改 cols」的路径都会让 Ctrl+Z 撒谎——`_SetCells` / `_AddCols` 两个 `QUndoCommand` 就够覆盖全部写操作，批量动作用 `beginMacro/endMacro` 裹。
2. **刷新用 `dataChanged`，绝不 `clear()` 重建**。现在 `gui.py` 的 `_populate_truth()` 每次 `tbl.clear()` + `resizeColumnsToContents()`，这正是「列宽被弹回」「编辑时闪」的根因；换 model 后这个问题自动消失（`test_08` 断言了列宽 173 px 在重绘/编辑/插列后纹丝不动）。

## 6. C3 波（v2 真值表模块）工作量估计

原型里已经跑通的代码量是**实测**的（`proto_qt.py` 去空行/注释 767 行，其中 demo 脚手架 61 行）。
产品化要加的是「接真实 `cur_cols`/`e_inputs`/`_commit()`」+ 错误路径 + 中文文案打磨，按经验 ×1.6。

| 功能点 | 原型行数 | 产品估计 | 说明 |
|---|---|---|---|
| `TruthModel` 骨架（形状/`data`/roles/`flags`/`headerData`） | 140 | 220 | 接真实 `e_inputs`（含 `is_dft_gate` / `mux_data_base` / `control` 的只读规则） |
| 写入口 + 校验 + 8 态上色 | 67 | 110 | 复用 `truth_edit`，`mux` 的 by_base 整表同步要额外一条路径 |
| 撤销栈（2 个 `QUndoCommand` + macro） | 45 | 80 | 加「列删除」「改名」「加反例」三个命令 |
| 列操作（加/复制/删/改名/加反例/高亮） | 75 | 130 | 接 `_commit()` + 预览/`.sv` 联动 |
| 复制 / 粘贴（含超行拒绝文案） | 70 | 110 | 文案要过一遍「说 IC 工程师的语言」 |
| CSV/xlsx 导入期望 | 46 | 90 | 加「列名模糊匹配提示」「导入前预览几列对上了」 |
| `TruthTableView`（键位/菜单/Ctrl+D/改名对话框） | 126 | 200 | 加 `QAction` 一套给菜单显示快捷键 |
| 冻结列（`NameModel` + `TruthPanel`） | 73 | 110 | 加行高同步的边角 + 信号名列右键菜单 |
| Delegate（灰字兜底 + 编辑器） | 25 | 60 | 加输入即时校验提示、placeholder 按行类型变 |
| 放大覆盖层 | 18 | 45 | 加「关掉时把焦点还回去」「记住上次大小」 |
| **小计（实现）** | **685** | **≈ 1155 行** | |
| 自动化测试 | 355 | **≈ 600 行 / 20–24 条** | 原型 12 条是骨架，产品要补 mux 行、DFT 行、只读行、负向列的用例 |

**折算**：实现 ≈ 1150 行 + 测试 ≈ 600 行。按这个仓库现有的节奏，**C3 波大约 3–4 个工作单元**（1 单元 = 一次「改完 → byte-gate 6 sha → 验证 → push」的闭环）：

1. Model + 撤销栈 + 校验 + 8 态色（含测试）——最重的一块，也是唯一有设计风险的一块
2. View 键位 + 复制粘贴 + 冻结列（含测试）
3. 列操作 + 右键菜单 + 放大层（含测试）
4. CSV/xlsx 导入 + 进度 + 文案打磨 + 与 `_commit()`/预览/`.sv` 的联动回归
